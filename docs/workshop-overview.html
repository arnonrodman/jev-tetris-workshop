Jev Tetris Workshop

A Tetris game that Jev, TypeSafe AI's "System One" model, plays on its own. Each new piece becomes one structured question: here are all the places this piece can land. Which is best? The page shows what Jev picked, how sure it was, and how the other options ranked.

The goal is to test Jev, not to build the strongest Tetris bot. Everything is set up so you can watch the decisions, change them, and measure them yourself.

Before you start

What is Jev?

Jev is a model from TypeSafe AI, announced in September 2026 and currently in early access. It belongs to TypeSafe's "System One" family: models built to make fast, structured decisions rather than to write text.

A chatbot takes a prompt and returns prose that your code has to parse. Jev takes a piece of state plus one or more typed questions, and returns typed answers with probabilities and a confidence score. There's no text to parse and no output format to hope for.

You send · state

The situation to judge: a string or a JSON object. Here, the board rows, the falling piece and the next pieces.

You send · questions

A map of ids to typed questions: Choice (pick one), Score (rate it) or Noul (yes or no), each with plain-language instructions.

You get · answers

One typed answer per question. For Choice: the chosen id, a probability for every option, and a 0–1 confidence.

Confidence is high when the probability sits mostly on one option and low when it's spread across several. That makes it a usable signal: act automatically when Jev is sure and fall back to something else when it isn't. Exercise 1 is built around this.

Jev or a regular LLM?

They answer different kinds of question. Jev is for decisions whose possible answers you already know. A general LLM such as Claude or GPT is for tasks where the output has to be written, reasoned out or invented.

Use Jev when
  • You can list the possible answers up front: pick one of N, rate on a scale, yes or no.
  • The decision runs inside a loop or at high volume, like once per game piece, request or event.
  • Your code acts on the answer directly, so it has to be typed and never malformed.
  • You want a calibrated confidence score to decide when to automate and when to escalate.
  • Latency or per-call cost matters more than a written explanation.
Use a regular LLM when
  • The output is open-ended: text, code, a summary, a plan, an email.
  • The options aren't known in advance and the model has to come up with them.
  • The task needs several steps of reasoning, tool use or back-and-forth conversation.
  • You need the model to explain its answer in words.
  • The input is long, unstructured content the model has to read and interpret.

They also work well together. An LLM can do the open-ended work, like writing the option descriptions or explaining a decision to a person. Jev can make the repeated, structured calls in the hot path. Tetris shows this split in miniature: code lists the options, Jev picks one, and plain code applies it.

Access is through POST https://api.typesafe.ai/v1/systemone or the Python SDK (pip install typesafe-sdk), using the model jev-latest. TypeSafe's published speed, cost and accuracy figures are the vendor's own benchmarks. This workshop is a way to check them yourself.

The core idea

Choose from a menu, don't steer the piece

A model that answers typed questions is a poor fit for pressing keys one at a time (left, left, rotate, drop). So the game changes the problem. For each falling piece, the browser tries every rotation in every column, drops it to where it would come to rest, and records what happens: lines cleared, new holes, stack height, surface bumpiness.

That list of legal final placements is the menu. Jev picks one item from it in a single request, and the game animates the piece into that spot. TypeSafe describes this pattern as a "smart if-statement": a fixed set of options, each described in plain language, decided in one fast call.

    state={"board_rows_top_to_bottom": board, "falling_piece": "T",

                         "lines, avoid creating holes, keep the stack low, and keep the surface flat.",
            criteria={"p0": "Rotation state 0, occupies column(s) ...", "p1": "...", ...},
        ),
    },
)

Jev's three question types

Why the game uses Choice

Placing a piece means picking exactly one option from a fixed list, and that is what Choice does. It accepts up to 255 options (one piece never has more than a few dozen). It also returns a probability for every option, which is what makes Jev's reasoning visible in the UI. The other two types have a role in the exercises.

What you can compare against

The built-in bot and manual play

Heuristic fallback

If Jev can't be reached (no API key, network error, or no answer within 4 seconds), the browser uses a hand-tuned bot so the game keeps running. The badge switches to heuristic fallback. It scores each placement with a classic formula:

−0.51 × aggregateHeight
+0.76 × linesCleared
−0.36 × holes
−0.18 × bumpiness

This also gives you a baseline to measure Jev against.

The workshop itself

Five exercises, in order

Each exercise builds on the previous one. Together they move from watching Jev, to adding questions, to measuring it with your own numbers.

  1. 1

    Read the confidence signal

    Watch the confidence bar for a few dozen pieces. Does it drop on boards with several similarly good placements and stay high when one is clearly best? Then make Jev's pick depend on confidence: when it's below about 0.3, have server/app.py return a flag that tells the browser to use the heuristic instead.

    server/app.pyconfidence gating
  2. 2

    Add a Noul question for Hold

    The AI never uses the hold slot yet. Add a second question to the same request, such as Noul(instructions="Would holding the current piece and playing the next one instead lead to a better outcome?"). On a confident yes, the browser calls holdPiece() and recomputes placements for the swapped piece.

    Noultwo questions, one request
  3. 3

    Add a Score question for board quality

    Ask Jev to rate how healthy the resulting board's surface is after each placement, and log that next to the heuristic's score. If the two disagree, that tells you something about how Jev judges a board.

    Scoresanity check
  4. 4

    Change the instructions, not the code

    Edit only the instructions string passed to Choice(...), for example "aggressively prioritize clearing multiple lines at once even if it means a taller stack", and see how Jev's play changes with no change to game logic.

    prompt-level behavior
  5. 5

    Measure agreement with the heuristic

    For every piece in a full game, log Jev's chosenId next to pickHeuristic(placements) and compute how often they agree. That gives you your own number to compare with TypeSafe's published benchmarks, which are vendor claims and haven't been independently verified.

    public/index.htmlyour own benchmark
Getting it running

Setup

The code is on GitHub at github.com/arnonrodman/jev-tetris-workshop. You need Git, Python 3.10 or newer and a TypeSafe API key from console.typesafe.ai/keys. It also runs without a key, using the heuristic, so you can rehearse the workshop before your access arrives.

git clone https://github.com/arnonrodman/jev-tetris-workshop.git
cd jev-tetris-workshop
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # set TYPESAFE_API_KEY=...
python server/app.py        # open http://localhost:3000 and press Start
Always "heuristic fallback"
Check the key in .env, restart the server, and look for errors in its terminal.
